# Local Android build (verified Windows recipe)

The Kshema mobile app uses a native module (`react-native-quick-crypto`), so it
cannot run in Expo Go — it needs a dev-client build that compiles native code.
This document captures the exact, validated steps for building and running the
Android dev client locally on Windows (including a locked-down, no-admin setup).

For the cloud alternative (EAS Build) and general notes, see `README.md`.

## Why the native project is not in git

The generated `android/` (and `ios/`) directories are **gitignored** and are
recreated by `expo prebuild`. After a fresh clone they do not exist yet — step 2
below regenerates them. This keeps build caches and generated files out of the
repo.

## Prerequisites (all installable without admin)

- **Node 20+** and **pnpm 11** (the root `package.json` pins the pnpm version).
- **Android Studio** with, via SDK Manager → SDK Tools:
  - SDK Platform **android-34**
  - **CMake 3.22.1**
  - **NDK 26.x**
- **JDK 17.** Gradle 8.8 / React Native 0.74 do **not** run on JDK 21+. Android
  Studio's bundled JBR may be too new, so install a standalone **Temurin 17** (a
  portable unzip is fine, e.g. `C:\Projects\OpenJDK17U-...\jdk-17.0.x`).
- **A short project path.** The C++ object paths (quick-crypto + OpenSSL) exceed
  the Windows path length limit when the repo sits under a deep folder such as
  a synced OneDrive directory, and CMake fails with `CMAKE_OBJECT_PATH_MAX`.
  Keep the repo near the drive root, e.g. `C:\Projects\Kshema`.

## Build steps

Run from the repo root, then `apps/mobile`:

```powershell
# 1. Install deps. The hoisted node-linker (pnpm-workspace.yaml) is required so
#    native autolinking resolves react-native / Expo modules in the monorepo.
pnpm install

# 2. Regenerate the native android project
cd apps/mobile
pnpm prebuild --platform android --clean

# 3. Point Gradle at the SDK. Because android/ is regenerated by prebuild,
#    recreate android/local.properties each time with your SDK path
#    (escaped backslashes), e.g.:
#      sdk.dir=C:\\Users\\<you>\\AppData\\Local\\Android\\Sdk

# 4. Build the debug APK with JDK 17 (env set for this shell only)
cd android
$env:JAVA_HOME="C:\Projects\OpenJDK17U-...\jdk-17.0.x"
$env:ANDROID_HOME="$env:LOCALAPPDATA\Android\Sdk"
$env:NODE_ENV="development"
$env:PATH="$env:JAVA_HOME\bin;$env:ANDROID_HOME\platform-tools;$env:PATH"
.\gradlew.bat :app:assembleDebug --no-daemon
# Output: android/app/build/outputs/apk/debug/app-debug.apk
```

## Install and run on an emulator or device

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb install -r app\build\outputs\apk\debug\app-debug.apk

# Start Metro from apps/mobile and leave it running:
#   pnpm start:dev
& $adb reverse tcp:8081 tcp:8081   # let the emulator reach Metro on localhost

# Tell the dev client to load the bundle from Metro:
& $adb shell am start -a android.intent.action.VIEW -d "in.kshema.app://expo-development-client/?url=http%3A%2F%2Flocalhost%3A8081" in.kshema.app
```

The app downloads the JS bundle from Metro and mounts `MainActivity`. JS-only
edits just need a reload; changing native dependencies requires a rebuild.

To verify success from the terminal (no screenshots needed):

```powershell
# Should print in.kshema.app/.MainActivity (not DevLauncherActivity or an error activity)
& $adb shell dumpsys activity activities | Select-String "ResumedActivity" | Select-Object -First 1
# Should show: Running "main" with {"rootTag":...} and no Invariant Violation
& $adb logcat -d | Select-String "ReactNativeJS"
```

## Architecture / native-module note (important)

The app builds on the **old React Native architecture** (`newArchEnabled=false`
in the generated `android/gradle.properties`), which `react-native-quick-crypto`
0.7.x targets.

`@craftzdog/react-native-buffer` depends on `react-native-quick-base64@^3`, but
3.x is **new-architecture-only**: it ships codegen specs and a CMakeLists but no
old-arch `android/build.gradle`, so autolinking silently skips it under RN 0.74.
That surfaces at runtime as:

```
Invariant Violation: TurboModuleRegistry.getEnforcing(...): 'QuickBase64' could not be found.
```

`pnpm-workspace.yaml` therefore pins `react-native-quick-base64` to **2.2.2**
(the last old-arch release that ships `android/build.gradle`) so it autolinks and
the native crypto stack loads. Keep that override while the app stays on the old
architecture.
